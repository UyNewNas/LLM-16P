# Agent16 Implementation Plan

> For agentic workers: implement the authorized GitHub Pages deliverable; user-specified hosting supersedes initial Sites scaffolding.

**Goal:** Publish a usable LLM questionnaire with machine-readable access to UyNewNas/LLM-16P.
**Architecture:** Static React UI plus a zero-dependency JavaScript instrument shared with Node; prebuilt Pages assets and reproducible Vite build.
**Tech stack:** React, TypeScript, CSS, native JS/Node test runner, Vite.
**Spec:** docs/superpowers/specs/2026-11-18-agent16-design.md

## Global constraints
- Original questions, 60/full and 20/quick, balanced dimensions and keying.
- No backend or fake POST endpoints; support repository subpath /LLM-16P/.
- No credentials, personal answers or generated demo assessments committed as real results.

## Review focus
Malformed imported JSON; boundary/empty scoring; localStorage corruption/quota; subpath assets/downloads; agent protocol version and reproducibility.

## Tasks
- [ ] Question bank and construct notes; verify unique IDs, count, balance.
- [ ] Shared scorer and questionnaire generation; test all-neutral, extreme poles, missing/null, invalid IDs/values/version, seed permutation.
- [ ] Website with complete manual/import/agent/history flows; browser verify.
- [ ] Agent JSON, schema, instructions, CLI, documentation and CI; smoke-test download/import.
- [ ] Fresh review, static build, publish source + built docs to requested repository, configure/check GitHub Pages if authorized access permits.

## Decisions
The user's GitHub Pages request replaces server APIs/MCP. No extra conversational approval gates: creation and publication are requested. Keep the initially created Site unpublished; don't use its identity or credentials in GitHub sources.
